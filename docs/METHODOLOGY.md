# 基准测试方法

本项目面向 **Minecraft Java 版 1.20.1**，用于比较用户配置的兼容实例在同一台主机、同一份预制单人世界中的表现。1.20.1 是当前探针实现和校验支持的游戏版本。待测整合包由用户选择，并应锁定各自版本、使用相同的 Minecraft 版本。

## 可比性条件

所有待测实例应使用同一个预制世界模板：固定种子、玩家位置和视角，旁观者模式、和平难度、白天、时间冻结，并预先生成测试视野内的区块。运行器为每次启动复制实例和世界，避免测量造成的世界改动影响下一次。配置加载器仅检查模板中存在 `level.dat`；**旁观者、天气、时间、区块范围和位置等条件须人工准备并核验**。当前工作负载只有 `static`（固定朝向）与 `rotate`（从保存朝向开始，每 12 秒转一圈）。飞行路线、区块生成、重型红石或多人服务器测试尚未实现，不应从这两种场景推断其表现。

控制硬件、操作系统、Java、Fabric/Quilt 运行环境、堆大小、显示器和窗口/帧缓冲分辨率、GPU 驱动、供电模式与散热状态。测试时关闭不必要的后台任务，保持同样的资源包、着色器及视频设置，并记录不能对齐的功能：例如着色器、连接纹理、动态光照和远景渲染。这些功能可能在不同整合包中默认启用或实现不同；需要人工检查“画面功能等价”，不能只因选项文本相同便视为等价。运行器覆盖 `options.txt` 中的垂直同步、帧率上限、失焦暂停、渲染距离、模拟距离、全屏及窗口尺寸默认值，但还应以探针 `world_ready.effective_settings` 和实际画面复核。默认 `maxFps:260` 在原版 1.20.1 代表“无限制”，并非 260 FPS 上限；若整合包改写该选项，应单独核查。探针要求窗口保持焦点、没有暂停界面，否则本次运行失败。

默认每组场景重复 **5 次**。每一重复轮将全部“实例 × 场景”随机排序，随机种子写入结果元数据；每次均启动新进程，在世界就绪后预热 **30 秒**，随后测量 **120 秒**，相邻运行间冷却 **10 秒**。可在配置中改动这些值，报告时必须一并公开。首轮仍保留并按重复编号标记。系统页缓存未清空，因此不能把启动或加载结果称为“冷启动”；复制实例也不等于清理操作系统、GPU 或 JVM 外部的所有缓存。

作为对照的基线若采用 Fabric 加探针，应标为 **“Fabric + probe 基线”**，不能标为纯原版。运行器在每个实例副本中安装同一探针，并记录世界、探针以及实例 `mods`、`config`、`options.txt` 的指纹。探针本身及运行条件必须在各组一致。

## 指标定义与边界

探针在客户端 `MinecraftClient.render` 的入口记录相邻游戏循环的间隔（毫秒）。这代表**客户端游戏循环间隔**，不是最终显示到屏幕的 GPU PresentMon 帧，也不直接测量输入延迟、屏幕撕裂或功耗。每次有效运行须有至少两帧，帧间隔总和至少覆盖设定测量时长的 90%，并取得进程资源采样。无效或失败运行保留错误原因，但不进入性能汇总。

每次运行独立计算：平均 FPS 为 `1000 / 平均帧间隔(ms)`；“1% low”和“0.1% low”分别取最慢的 `ceil(帧数 × 1%)`、`ceil(帧数 × 0.1%)` 帧，计算 `1000 / 这些帧的平均间隔(ms)`。帧时间 p50、p95、p99 使用升序最近秩法，即排序后第 `ceil(n × p)` 个值。卡顿率是**严格大于 50 ms** 的帧数除以观测帧间隔总和（分钟）。这些值均不是对瞬时 FPS 取算术平均。

资源采样来自被探针报告的游戏 Java 进程，默认约每 0.5 秒一次。CPU 均值/峰值取采样值；按 [psutil 的进程 CPU 定义](https://psutil.readthedocs.io/stable/#psutil.Process.cpu_percent)，**100% 约等于占满一个逻辑核心**，多线程进程可超过 100%。内存均值/峰值为该进程 RSS 的 MiB（`2^20` 字节），不是私有内存、Java 堆、系统总内存或显存；[psutil 的 RSS 说明](https://psutil.readthedocs.io/stable/#psutil.Process.memory_info) 包含平台差异。I/O 字节计数和系统内存占用可保存在原始数据中，但当前汇总不计算 I/O 速率。GPU 功率、GPU 显存和整机功耗未采集；缺失字段不代表数值为零。

“启动时间”是 JVM uptime 从 JVM 启动到主菜单出现的毫秒数，**不含启动器准备与进程创建之前的时间**。“世界加载时间”是 `world_ready.jvm_uptime_ms - menu.jvm_uptime_ms`；它还包含主菜单出现后探针安排自动打开世界的时间，因此不是独立的磁盘读盘耗时。`world_ready` 要求世界、玩家已存在且无打开的界面，但不保证所有背景加载或渲染缓存已稳定。

报告按“实例 × 场景”分组，**先算每次运行，再对有效运行的各项指标分别取中位数**，绝不把不同重复的帧合并。平均 FPS 的变异系数是各次运行平均 FPS 的样本标准差除以其算术平均值。报告的平均 FPS 95% 区间是对**运行级平均 FPS** 固定随机种子做 10,000 次有放回重采样、再取百分位的 bootstrap 区间；它不是组内 FPS 中位数的区间。少于 5 次有效运行标记为“不确定”，并公开总重复数、成功数和失败数。此区间描述当前有限重复的波动，不消除环境差异或证明整合包之间存在因果差距。`demo` 生成的是明确标记的合成数据、虚构整合包名，仅用于查看报表格式。

实际运行与遥测字段见 [`PROTOCOL.md`](PROTOCOL.md)。
